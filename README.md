## 一、做法回顾  

### 1.1 从复现论文到简化思路  

比赛初期，我们按部就班地复现了 PMG、DCL 等细粒度分类的经典论文，也尝试了 NUST 实验室开源的一些模型。  
结果很一致：**全都被算力卡死**。  

后来我们尝试对数据集做手工清晰化处理，并在 400 类上做实验，效果依然不理想。  

于是我们换了个思路：**干脆把它当作一个普通的多分类任务来做**。  
这样一来，模型大幅简化，训练时间压缩到原来的 **1/10**，最终也拿到了不错的分数。  

---

### 1.2 图像尺寸的选择很关键  

数据处理阶段，需要根据模型特点选择最合适的 `image_size`：  

- 尺寸太小（比如 64×64），信息丢失严重，分数会很低；  
- 尺寸太大（比如 512×512），算力消耗大，收益却不一定高。  
- 要找到一个**性价比最高**的平衡点。  

很多选手一上来就固定用某个尺寸，容易踩坑。  

---

### 1.3 数据增强与预测脚本的对齐  

常见的数据增强方法效果有限，可以多关注 **TTA（Test Time Augmentation）** 这类策略。  

更重要的一点是：**预测脚本必须与训练时的处理方式严格对齐**。  

举个例子：  
- 如果你训练时用的是 `448×448 → 224×224` 的裁剪，或者用了多尺度的 TTA 验证；  
- 那预测时也要用同样的流程，模型才能“认出”输入数据的样式。  

这个细节很多选手忽略了，但恰恰是提升分数的重要一环。

## 二、两个值得注意的“漏洞”  

### 2.1 隐藏预训练权重  

比赛规定：**只能使用 ImageNet-1k 上的预训练权重**。  

我们在初期因为失误，用到了 **ImageNet-21k** 的权重，结果在 5000 类上效果惊人，拟合速度极快。  

那么问题来了：能不能绕过检测？  
比如把 21k 的权重文件 **重命名为 ImageNet-1k 的格式**，再封装成一个接口上传？  

（可以参考 PyTorch 官方文档中不同权重的命名方式）  

另外，官方后来更新了 ImageNet-1k 的新版权重，比旧版效果提升了 1-2 个点。  
这说明：**即便是同源的预训练权重，版本不同也会带来差异**。  

---

### 2.2 回溯答案（数据溯源漏洞）  

这个方法的可操作性不如 2.1，但在理论上确实存在。  

比赛方提供的 webfg400/5000 数据集，其实是在**原始完整数据集的基础上做了改名和删减**。  
如果我们能回溯到原始数据集，就能直接拿到每张图片的真实标签。  

怎么做？  
- 原始网络爬取的数据中，每个类别的图片尺寸往往形成一个**固定的字符串模式**；  
- 虽然图片名被改了，但图片本身的尺寸信息不会变；  
- 对于每个类别，这个尺寸字符串是唯一的。  

于是，只要你能通过某种方式（比如信息编码、数据溯源）还原出原始数据，就能**反向推导出答案**。  
这也是为什么比赛中会出现“满分”提交的原因之一。
